### 功能：递归

描述：在树形结构的表里，从某些行出发，沿着上级或下级的关系，一层一层地找出相关的记录。

语法：递归 [方向] 起始 <起始条件式> 选出列 {<计算式> [递归项 <递归计算式>] [命名 <新列名>]} [层次 <层次列名>] [主键 <主键字段>] [父列 <父列字段>] [条件 <条件式>]

说明：这里的"树形结构"是指，表里有两个字段，一个字段能唯一区分每一行(比如员工编号)，另一个字段记录"这一行的上级是哪一行"(比如上级编号)；这两个字段就把整个表组织成了一棵树，最上面那一行没有上级，是树的根。

本功能相当于SQL里的递归子查询(WITH RECURSIVE)，并在此基础上做了归纳和扩展：参数**起始**相当于SQL里最先查出的那部分行，参数**方向**、**父列**、**主键**决定后面怎么一层层地找下去，参数**层次**相当于递归的层数。

> 本文所有例子都用下面这个员工表(焦点表)。其中，员工编号能唯一区分每一行；上级编号记录"这一行的上级是谁"；推荐人编号记录"这一行是谁推荐来的"；张伟既没有上级、也没有推荐人，所以他是两棵树的根。

```
员工编号	姓名	上级编号	推荐人编号	部门	工资
E01	张伟			总经理室	30000
E02	李娜	E01	E01	销售部	15000
E03	王强	E01	E02	技术部	18000
E04	赵敏	E02	E03	销售部	9000
E05	刘洋	E02	E03	销售部	8000
E06	陈静	E03	E01	技术部	12000
E07	杨帆	E03	E06	技术部	7000
E08	周涛	E04	E07	销售部	5000
```

说明：按**上级编号**看，这棵树是：张伟下面有李娜、王强；李娜下面有赵敏、刘洋；王强下面有陈静、杨帆；赵敏下面是周涛。按**推荐人编号**看，是另一棵树：张伟推荐了李娜、陈静；李娜推荐了王强；王强推荐了赵敏、刘洋；陈静推荐了杨帆；杨帆推荐了周涛。

#### 参数说明(按由浅入深的顺序)

前面的**方向**、**起始**、**选出列**这3个参数是必要的，只写这3个就能用；**父列**和**条件**至少要写一个：写了**父列**，本功能就沿父子关系一层一层地找；不写**父列**时，必须用**条件**自己描述怎么一层一层地找。后面的**项**、**命名**、**递归项**、**层次**、**主键**是可选的，加上以后可以写计算列、给列起名、把上一层的计算结果带到下一层、增加层次号列、指定主键。

参数：**方向**

往哪个方向找。必要参数；枚举类型；参数名必须省略，不能省略参数值。有两个枚举值：

- 向上：从起始行出发找上级，也就是沿着参数**父列**一直往根的方向找。
- 向下：从起始行出发找下级，也就是沿着参数**父列**一直往叶子的方向找。

> 例子：从赵敏出发，向上找出她的所有上级。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 姓名 父列 上级编号

结果：

```
姓名
赵敏
李娜
张伟
```

解释：赵敏是起始行(第1层)；她的上级是李娜(第2层)；李娜的上级是张伟(第3层)；张伟没有上级，就不再有下一层了。结果里行的先后顺序，就是一层一层找上来的顺序。

> 例子：从张伟出发，向下找出他的所有下级。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 父列 上级编号

结果：

```
姓名
张伟
李娜
王强
赵敏
刘洋
陈静
杨帆
周涛
```

解释：张伟是第1层，李娜和王强是第2层，赵敏、刘洋、陈静、杨帆是第3层，周涛是第4层。同一层的记录排在一起，同一层里按焦点表原来的顺序排列。

参数：**起始**

从哪些行开始找。必要参数；类型是条件式；参数名不能省略。你写一个条件式，满足它的行就是起点，起点本身也会出现在结果里(算第1层)。

起点可以只有一行，也可以有多行；可以是根(没有上级的行)，也可以是树中间的任何一行。多行起点时，起点按焦点表原来的顺序依次处理，每个起点带出自己找到的行，重复的行保留（向上找时，每个起点带出自己到根的整条链，见下例）。

> 例子：从李娜开始，向下找出她和她的所有下级。

SQLazy：递归 向下 起始 (姓名="李娜") 选出列 姓名 父列 上级编号

结果：

```
姓名
李娜
赵敏
刘洋
周涛
```

解释：这次的起点是李娜，不是根，所以结果里没有张伟、王强、陈静、杨帆，他们不在李娜下面。

> 例子：技术部有三个人(王强、陈静、杨帆)，从他们三个一起出发向上找各自的上级。

SQLazy：递归 向上 起始 (部门="技术部") 选出列 姓名 父列 上级编号

结果：

```
姓名
王强
张伟
陈静
王强
张伟
杨帆
王强
张伟
```

解释：条件"部门='技术部'"同时选中3行(王强、陈静、杨帆)，这3行都是起点，都是第1层。多行起点时，每个起点依次带出自己到根的整条链：王强的上级是张伟；陈静的上级是王强、王强的上级是张伟；杨帆的上级是王强、王强的上级是张伟。本功能不再去掉重复的行，所以王强出现3次(1次起点、2次上级)、张伟出现3次(都是上级)。

参数：**选出列**

说明结果里要哪些列。必要参数；类型是复合参数(由多个子参数组成的一个参数)；参数名不能省略。

本参数由一组或多组参数组成，每组表示结果里的一个列，由2个参数组成：一个是计算式(参数名必须省略)，另一个是它的列名(子参数**命名**)；需要把上一层的计算结果带到下一层时，每组还可以再加一个递归计算式(子参数**递归项**)。需要多个列时，就写多组，组与组之间用逗号分隔。

> 例子：从张伟出发向下找出全部记录，结果里要姓名和部门两个列。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 部门 父列 上级编号

结果：

```
姓名	部门
张伟	总经理室
李娜	销售部
王强	技术部
赵敏	销售部
刘洋	销售部
陈静	技术部
杨帆	技术部
周涛	销售部
```

> 例子：同一个查找，结果里要姓名、部门、工资三个列。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 部门, 工资 父列 上级编号

结果：

```
姓名	部门	工资
张伟	总经理室	30000
李娜	销售部	15000
王强	技术部	18000
赵敏	销售部	9000
刘洋	销售部	8000
陈静	技术部	12000
杨帆	技术部	7000
周涛	销售部	5000
```

解释：结果里列的先后顺序，就是你写"选出列"的先后顺序。

参数：**父列**

告诉本功能"哪一列记录了这一行的上级"。非必要参数，但与参数**条件**至少要写一个；类型是(列)标识；参数名不能省略，不能省略参数值。本功能就是靠这一列，一层层往上或往下找的。

用不同的父列，得到的是不同的树形结构，结果也不同。

> 例子：按上级编号这棵树，从赵敏出发向上找出她的所有上级。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 姓名, 部门 父列 上级编号

结果：

```
姓名	部门
赵敏	销售部
李娜	销售部
张伟	总经理室
```

> 例子：换成推荐人编号这棵树，从张伟出发向下找出全部记录，结果与上例不同。

SQLazy：递归 向下 起始 (推荐人编号 为空) 选出列 姓名, 部门 父列 推荐人编号

结果：

```
姓名	部门
张伟	总经理室
李娜	销售部
陈静	技术部
王强	技术部
杨帆	技术部
赵敏	销售部
刘洋	销售部
周涛	销售部
```

解释：按推荐关系，张伟推荐了李娜、陈静；李娜推荐了王强；王强推荐了赵敏、刘洋；陈静推荐了杨帆；杨帆推荐了周涛。这棵树和按上级编号看的那棵树不一样，所以结果也不一样。

参数：**项**

子参数**项**是参数**选出列**里每一组的计算式，也就是结果里这个列的值怎么算出来。必要参数；类型是计算式；参数名必须省略，不能省略参数值。

可以直接写一个列名，比如：姓名、工资；也可以写关于一个列或多个列的计算式，比如：工资*0.1、单价*数量*0.1。

注意，本参数不支持跨行计算和聚合计算，即计算式里不能含有F[i]、F[a:b]形式的相对位置计算，也不能有集合的求和、平均等聚合计算。

> 例子：从赵敏出发向上找出她的所有上级，结果里要工资这一个列。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 工资 父列 上级编号

结果：

```
工资
9000
15000
30000
```

> 例子：从赵敏出发向上找出她的所有上级，用计算式"工资*1.1"算出调整后工资。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 工资*1.1 父列 上级编号

结果：

```
工资*1.1
9900
16500
33000
```

解释：本组的计算式不是单个列名，所以系统自动拿计算式本身当列名，列名就是"工资*1.1"。想让这个列有个像样的名字，就用下面讲的参数**命名**。

参数：**命名**

子参数**命名**是参数**选出列**里每一组的列名，也就是子参数**项**算出来的这一列在结果里叫什么。非必要参数，省略时沿用原来的列名(计算式不是单列时，系统自动拿计算式当列名)；类型是(列)标识；参数名不能省略，不能省略参数值。注意，本参数要和同一组的**项**搭配使用。

> 例子：同一个查找，把上面那个"工资*1.1"的列命名为"调整后工资"。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 工资*1.1 命名 调整后工资 父列 上级编号

结果：

```
调整后工资
9900
16500
33000
```

> 例子：从张伟出发向下找出全部记录，把姓名这一列改名为"员工"。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 命名 员工 父列 上级编号

结果：

```
员工
张伟
李娜
王强
赵敏
刘洋
陈静
杨帆
周涛
```

参数：**递归项**

子参数**递归项**是参数**选出列**里每一组的"递归计算式"，用来算这一列在下一层上的值。非必要参数，省略时就用同一组的**项**；类型是计算式；参数名不能省略，不能省略参数值。

前面讲过的**项**算的是第一层(起始行)的值；加了**递归项**以后，从第二层起，这一列的值改用**递归项**来算。它的用处是把上一层的计算结果带到下一层：在递归项里，标识后面加@表示"上一轮结果里这一列的值"，不加@表示"本行在原表里的列"。所以像累计、路径、继承上级属性这类必须用到上一层结果的，就得靠本参数。

注意，本参数同样不支持F[i]、F[a:b]形式的相对位置计算，也不支持集合的求和、平均等聚合计算。

> 例子：从张伟出发向下找出全部记录，同时算出每个人的累计工资(自己的工资加上各级上级的工资)。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 工资 递归项 (ifn(累计工资@, 0) + 工资) 命名 累计工资 父列 上级编号

结果：

```
姓名	累计工资
张伟	30000
李娜	45000
王强	48000
赵敏	54000
刘洋	53000
陈静	60000
杨帆	55000
周涛	59000
```

解释：张伟是起始行，用**项**"工资"算出30000；往下每一层由**递归项**算：`累计工资@`取上一层(就是自己的上级)的累计工资，再加上自己的工资，所以李娜=30000+15000=45000、王强=30000+18000=48000、赵敏=45000+9000=54000。式子里`ifn(…, 0)`的0只是兜底，正常递归时上一层一定有值，用不到它。

> 例子：从张伟出发向下找出全部记录，同时为每个人算出从根到自己的姓名路径。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 (concat(姓名, "/")) 递归项 (concat(ifn(路径@, ""), 姓名, "/")) 命名 路径 父列 上级编号

结果：

```
路径
张伟/
张伟/李娜/
张伟/王强/
张伟/李娜/赵敏/
张伟/李娜/刘洋/
张伟/王强/陈静/
张伟/王强/杨帆/
张伟/李娜/赵敏/周涛/
```

解释：起始行用**项**算出"张伟/"；往下每一层用**递归项**，`路径@`就是上一层那一行的路径，接上自己的姓名和斜杠，所以赵敏这一行是"张伟/李娜/赵敏/"。

参数：**层次**

加上本参数后，结果里会多出一个层次号列，表示每一行在第几层(起始行是第1层)。非必要参数；类型是(列)标识，也就是层次号列的名称；参数名不能省略，不能省略参数值。

> 例子：从张伟出发向下找出全部记录，并且要一个层次号列，列名叫"层级"。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 层次 层级 父列 上级编号

结果：

```
姓名	层级
张伟	1
李娜	2
王强	2
赵敏	3
刘洋	3
陈静	3
杨帆	3
周涛	4
```

> 例子：从赵敏出发向上找出她的所有上级，并且要一个层次号列，列名叫"层级"。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 姓名 层次 层级 父列 上级编号

结果：

```
姓名	层级
赵敏	1
李娜	2
张伟	3
```

解释：不管向上还是向下，起始行都是第1层，往上或往下每一层加1。

参数：**主键**

能唯一区分每一行的字段，本功能用它来判断"这一行是不是已经找过了"。非必要参数，省略时用表的主键；类型是(列)标识；参数名不能省略，不能省略参数值。

注意，本参数只是内部用来认行的，不会出现在结果里，结果里有哪些列由参数**选出列**决定。

> 例子：从张伟出发向下找出全部记录，并且写出主键是员工编号。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 层次 层级 主键 员工编号 父列 上级编号

结果：

```
姓名	层级
张伟	1
李娜	2
王强	2
赵敏	3
刘洋	3
陈静	3
杨帆	3
周涛	4
```

> 例子：员工表的主键就是员工编号，所以本参数可以省略，结果与上例相同。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 层次 层级 父列 上级编号

结果：

```
姓名	层级
张伟	1
李娜	2
王强	2
赵敏	3
刘洋	3
陈静	3
杨帆	3
周涛	4
```

参数：**条件**

递归条件。非必要参数；类型是条件式；参数名不能省略，不能省略参数值。

注意，本参数与参数**父列**配合使用：写了**父列**时，本参数是附加条件；没写**父列**时，本参数就当作递归条件。条件式里，标识后面加@表示取"上一轮选出表"里的值，不加@表示取本轮原表(即锚点表)的列。

注意，**父列**和本参数一起用时，本参数是"到这一行为止"的：某一层找出来的行不满足条件，这一行不出现在结果里，也不再从这一行继续找，它后面的整条链都没有了。下面第1个例子里，第2层的赵敏(9000)满足条件，继续往上；第3层的李娜(15000)不满足条件，链就断了，更上面的张伟也不出现。

> 例子：从周涛出发向上找，但结果里只要工资低于10000的行。

SQLazy：递归 向上 起始 (姓名="周涛") 选出列 姓名 层次 层级 父列 上级编号 条件 (工资 < 10000)

结果：

```
姓名	层级
周涛	1
赵敏	2
```

解释：这次写了**父列**，所以**条件**只是附加条件，符合它的行才留在结果里。周涛(5000)、赵敏(9000)满足条件；再往上的李娜(15000)不满足条件，链到这里就断了，更上面的张伟(30000)也不会出现。层次号照旧按"第几层"算，不受条件影响。

> 例子：不写**父列**，改用**条件**自己描述怎么一层一层往下找。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 员工编号, 姓名 条件 (上级编号 = 员工编号@)

结果：

```
员工编号	姓名
E01	张伟
E02	李娜
E03	王强
E04	赵敏
E05	刘洋
E06	陈静
E07	杨帆
E08	周涛
```

解释：这次没写**父列**，**条件**本身就是递归条件。上一轮找出张伟(E01)，这一轮就用"上级编号 = E01"去找，找到李娜(E02)、王强(E03)；下一轮再分别用"上级编号 = E02"、"上级编号 = E03"去找，找到赵敏、刘洋、陈静、杨帆；最后一轮用"上级编号 = E04"找到周涛。标识后面加@表示取"上一轮选出表"里的值，本例把员工编号写进了**选出列**，所以 员工编号@ 取的就是上一轮那一行的员工编号。本例的结果和写"父列 上级编号"完全一样。
