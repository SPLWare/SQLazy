### 功能：递归

描述：在树形结构的表里，从某些行出发，沿着上级或下级的关系，一层一层地找出相关的记录。

语法：递归 [方向] 起始 <起始条件式> 选出列 {<计算式> [命名 <新列名>]} [层次 <层次列名>] [主键 <主键字段>] [父列 <父列字段>] [条件 <条件式>]

说明：这里的"树形结构"是指，表里有两个字段，一个字段能唯一区分每一行(比如员工编号)，另一个字段记录"这一行的上级是哪一行"(比如上级编号)；这两个字段就把整个表组织成了一棵树，最上面那一行没有上级，是树的根。

本功能相当于SQL里的递归子查询(WITH RECURSIVE)，并在此基础上做了归纳和扩展：参数**起始**相当于SQL里最先查出的那部分行，参数**方向**、**父列**、**主键**决定后面怎么一层层地找下去，参数**层次**相当于递归的层数。

> 本文所有例子都用下面这个员工表(焦点表)。其中，员工编号能唯一区分每一行；上级编号记录"这一行的上级是谁"；推荐人编号记录"这一行是谁推荐来的"；张伟既没有上级、也没有推荐人，所以他是两棵树的根。

```
员工编号	姓名	上级编号	推荐人编号	部门	工资
E01	张伟			总经理室	30000
E02	李娜	E01	E01	销售部	15000
E03	王强	E01	E02	技术部	18000
E04	赵敏	E02	E03	销售部	9000
E05	刘洋	E02	E03	销售部	8000
E06	陈静	E03	E01	技术部	12000
E07	杨帆	E03	E06	技术部	7000
E08	周涛	E04	E07	销售部	5000
```

说明：按**上级编号**看，这棵树是：张伟下面有李娜、王强；李娜下面有赵敏、刘洋；王强下面有陈静、杨帆；赵敏下面是周涛。按**推荐人编号**看，是另一棵树：张伟推荐了李娜、陈静；李娜推荐了王强；王强推荐了赵敏、刘洋；陈静推荐了杨帆；杨帆推荐了周涛。

#### 参数说明(按由浅入深的顺序)

前面的**方向**、**起始**、**选出列**、**父列**这4个参数是必要的，只写这4个就能用；后面的**项**、**命名**、**层次**、**主键**、**条件**是可选的，加上以后可以写计算列、给列起名、增加层次号列、指定主键、过滤结果。

参数：**方向**

往哪个方向找。必要参数；枚举类型；参数名必须省略，不能省略参数值。有两个枚举值：

- 向上：从起始行出发找上级，也就是沿着参数**父列**一直往根的方向找。
- 向下：从起始行出发找下级，也就是沿着参数**父列**一直往叶子的方向找。

> 例子：从赵敏出发，向上找出她的所有上级。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 姓名 父列 上级编号

结果：

```
姓名
赵敏
李娜
张伟
```

解释：赵敏是起始行(第1层)；她的上级是李娜(第2层)；李娜的上级是张伟(第3层)；张伟没有上级，就不再有下一层了。结果里行的先后顺序，就是一层一层找上来的顺序。

> 例子：从张伟出发，向下找出他的所有下级。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 父列 上级编号

结果：

```
姓名
张伟
李娜
王强
赵敏
刘洋
陈静
杨帆
周涛
```

解释：张伟是第1层，李娜和王强是第2层，赵敏、刘洋、陈静、杨帆是第3层，周涛是第4层。同一层的记录排在一起，同一层里按焦点表原来的顺序排列。

参数：**起始**

从哪些行开始找。必要参数；类型是条件式；参数名不能省略。你写一个条件式，满足它的行就是起点，起点本身也会出现在结果里(算第1层)。

起点可以只有一行，也可以有多行；可以是根(没有上级的行)，也可以是树中间的任何一行。

> 例子：从李娜开始，向下找出她和她的所有下级。

SQLazy：递归 向下 起始 (姓名="李娜") 选出列 姓名 父列 上级编号

结果：

```
姓名
李娜
赵敏
刘洋
周涛
```

解释：这次的起点是李娜，不是根，所以结果里没有张伟、王强、陈静、杨帆，他们不在李娜下面。

> 例子：技术部有三个人(王强、陈静、杨帆)，从他们三个一起出发向上找各自的上级。

SQLazy：递归 向上 起始 (部门="技术部") 选出列 姓名 父列 上级编号

结果：

```
姓名
王强
陈静
杨帆
张伟
```

解释：条件"部门='技术部'"同时选中3行(王强、陈静、杨帆)，这3行都是起点，都是第1层；再往上找一层，他们的上级都是张伟，张伟是第2层。多行起点时，本功能会自动去掉重复的行，张伟只出现一次。

参数：**选出列**

说明结果里要哪些列。必要参数；类型是复合参数(由多个子参数组成的一个参数)；参数名不能省略。

本参数由一组或多组参数组成，每组表示结果里的一个列，由2个参数组成：一个是计算式(参数名必须省略)，另一个是它的列名(子参数**命名**)。需要多个列时，就写多组，组与组之间用逗号分隔。

> 例子：从张伟出发向下找出全部记录，结果里要姓名和部门两个列。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 部门 父列 上级编号

结果：

```
姓名	部门
张伟	总经理室
李娜	销售部
王强	技术部
赵敏	销售部
刘洋	销售部
陈静	技术部
杨帆	技术部
周涛	销售部
```

> 例子：同一个查找，结果里要姓名、部门、工资三个列。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 部门, 工资 父列 上级编号

结果：

```
姓名	部门	工资
张伟	总经理室	30000
李娜	销售部	15000
王强	技术部	18000
赵敏	销售部	9000
刘洋	销售部	8000
陈静	技术部	12000
杨帆	技术部	7000
周涛	销售部	5000
```

解释：结果里列的先后顺序，就是你写"选出列"的先后顺序。

参数：**父列**

告诉本功能"哪一列记录了这一行的上级"。必要参数；类型是(列)标识；参数名不能省略，不能省略参数值。本功能就是靠这一列，一层层往上或往下找的。

用不同的父列，得到的是不同的树形结构，结果也不同。

> 例子：按上级编号这棵树，从赵敏出发向上找出她的所有上级。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 姓名, 部门 父列 上级编号

结果：

```
姓名	部门
赵敏	销售部
李娜	销售部
张伟	总经理室
```

> 例子：换成推荐人编号这棵树，从张伟出发向下找出全部记录，结果与上例不同。

SQLazy：递归 向下 起始 (推荐人编号 为空) 选出列 姓名, 部门 父列 推荐人编号

结果：

```
姓名	部门
张伟	总经理室
李娜	销售部
陈静	技术部
王强	技术部
杨帆	技术部
赵敏	销售部
刘洋	销售部
周涛	销售部
```

解释：按推荐关系，张伟推荐了李娜、陈静；李娜推荐了王强；王强推荐了赵敏、刘洋；陈静推荐了杨帆；杨帆推荐了周涛。这棵树和按上级编号看的那棵树不一样，所以结果也不一样。

参数：**项**

子参数**项**是参数**选出列**里每一组的计算式，也就是结果里这个列的值怎么算出来。必要参数；类型是计算式；参数名必须省略，不能省略参数值。

可以直接写一个列名，比如：姓名、工资；也可以写关于一个列或多个列的计算式，比如：工资*0.1、单价*数量*0.1。

注意，本参数不支持跨行计算和聚合计算，即计算式里不能含有F[i]、F[a:b]形式的相对位置计算，也不能有集合的求和、平均等聚合计算。

> 例子：从赵敏出发向上找出她的所有上级，结果里要工资这一个列。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 工资 父列 上级编号

结果：

```
工资
9000
15000
30000
```

> 例子：从赵敏出发向上找出她的所有上级，用计算式"工资*1.1"算出调整后工资。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 工资*1.1 父列 上级编号

结果：

```
工资*1.1
9900
16500
33000
```

解释：本组的计算式不是单个列名，所以系统自动拿计算式本身当列名，列名就是"工资*1.1"。想让这个列有个像样的名字，就用下面讲的参数**命名**。

参数：**命名**

子参数**命名**是参数**选出列**里每一组的列名，也就是子参数**项**算出来的这一列在结果里叫什么。非必要参数，省略时沿用原来的列名(计算式不是单列时，系统自动拿计算式当列名)；类型是(列)标识；参数名不能省略，不能省略参数值。注意，本参数要和同一组的**项**搭配使用。

> 例子：同一个查找，把上面那个"工资*1.1"的列命名为"调整后工资"。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 工资*1.1 命名 调整后工资 父列 上级编号

结果：

```
调整后工资
9900
16500
33000
```

> 例子：从张伟出发向下找出全部记录，把姓名这一列改名为"员工"。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 命名 员工 父列 上级编号

结果：

```
员工
张伟
李娜
王强
赵敏
刘洋
陈静
杨帆
周涛
```

参数：**层次**

加上本参数后，结果里会多出一个层次号列，表示每一行在第几层(起始行是第1层)。非必要参数；类型是(列)标识，也就是层次号列的名称；参数名不能省略，不能省略参数值。

> 例子：从张伟出发向下找出全部记录，并且要一个层次号列，列名叫"层级"。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 层次 层级 父列 上级编号

结果：

```
姓名	层级
张伟	1
李娜	2
王强	2
赵敏	3
刘洋	3
陈静	3
杨帆	3
周涛	4
```

> 例子：从赵敏出发向上找出她的所有上级，并且要一个层次号列，列名叫"层级"。

SQLazy：递归 向上 起始 (姓名="赵敏") 选出列 姓名 层次 层级 父列 上级编号

结果：

```
姓名	层级
赵敏	1
李娜	2
张伟	3
```

解释：不管向上还是向下，起始行都是第1层，往上或往下每一层加1。

参数：**主键**

能唯一区分每一行的字段，本功能用它来判断"这一行是不是已经找过了"。非必要参数，省略时用表的主键；类型是(列)标识；参数名不能省略，不能省略参数值。

注意，本参数只是内部用来认行的，不会出现在结果里，结果里有哪些列由参数**选出列**决定。

> 例子：从张伟出发向下找出全部记录，并且写出主键是员工编号。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 层次 层级 主键 员工编号 父列 上级编号

结果：

```
姓名	层级
张伟	1
李娜	2
王强	2
赵敏	3
刘洋	3
陈静	3
杨帆	3
周涛	4
```

> 例子：员工表的主键就是员工编号，所以本参数可以省略，结果与上例相同。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名 层次 层级 父列 上级编号

结果：

```
姓名	层级
张伟	1
李娜	2
王强	2
赵敏	3
刘洋	3
陈静	3
杨帆	3
周涛	4
```

参数：**条件**

对结果做额外的筛选，只保留满足这个条件的行。非必要参数；类型是条件式；参数名不能省略。

注意，本参数只是把结果里不满足条件的行去掉，不会影响本功能继续往下一层找。

> 例子：从张伟出发向下找出全部记录，结果里只要工资不低于8000的。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 工资 条件 (工资>=8000) 父列 上级编号

结果：

```
姓名	工资
张伟	30000
李娜	15000
王强	18000
赵敏	9000
刘洋	8000
陈静	12000
```

> 例子：从张伟出发向下找出全部记录，结果里只要销售部的。

SQLazy：递归 向下 起始 (上级编号 为空) 选出列 姓名, 部门 条件 (部门="销售部") 父列 上级编号

结果：

```
姓名	部门
李娜	销售部
赵敏	销售部
刘洋	销售部
周涛	销售部
```

解释：张伟是总经理室，也被条件去掉了；但他的下级李娜、王强照常往下找，所以李娜这一支的记录仍然出现在结果里。这说明参数**条件**只筛结果，不影响往下找。
